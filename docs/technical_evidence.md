## Build and reproduce

Use the existing project environment; no dependencies were added. Native integration requires Windows desktop Excel with Power Query and PowerShell COM automation. Python stages can run in WSL. The builder must receive a Windows-native input-folder path because Excel resolves it later; a `/mnt/c/...` path is unsuitable inside the workbook.

Run from the project directory in WSL. Replace the generic Windows project path with the checkout location. Use fresh build and output filenames for each run; never overwrite a manually finished native workbook.

```bash
# First export, when reports/excel/inputs does not exist
.venv/bin/python python/export_excel_inputs.py
# To deliberately replace existing generated inputs, use this instead
.venv/bin/python python/export_excel_inputs.py --replace

.venv/bin/python python/build_excel_workbook.py \
  --inputs reports/excel/inputs \
  --output reports/excel/R2_review_build_v4.xlsx \
  --excel-input-folder 'C:/portfolio/projects/r2-returns-adjusted-customer-value/reports/excel/inputs'

powershell.exe -NoProfile -ExecutionPolicy Bypass \
  -File 'C:/portfolio/projects/r2-returns-adjusted-customer-value/reports/excel/finish_workbook.ps1' \
  -InputWorkbook 'C:/portfolio/projects/r2-returns-adjusted-customer-value/reports/excel/R2_review_build_v4.xlsx' \
  -OutputWorkbook 'C:/portfolio/projects/r2-returns-adjusted-customer-value/reports/excel/R2_review_v4.xlsx'

powershell.exe -NoProfile -ExecutionPolicy Bypass \
  -File 'C:/portfolio/projects/r2-returns-adjusted-customer-value/reports/excel/validate_workbook.ps1' \
  -InputWorkbook 'C:/portfolio/projects/r2-returns-adjusted-customer-value/reports/excel/R2_review_v4.xlsx' \
  -InputFolder 'C:/portfolio/projects/r2-returns-adjusted-customer-value/reports/excel/inputs'
```

The two exporter invocations above are alternatives. `--replace` deliberately replaces the generated input folder after validating and staging its contents. It is not permission to replace native workbooks. Both the builder and native finisher refuse an existing output path. The finisher requires both `InputWorkbook` and `OutputWorkbook`; the validator requires both `InputWorkbook` and `InputFolder`.

Never save a finished native workbook through openpyxl: doing so can destroy Power Query and slicer extensions. Rebuild from the planning template into a new intermediate `.xlsx`, then finish with Excel. Preserve manual native work separately. `R2_template.xltx` remains a distinct planning deliverable generated by `python/build_excel_skeleton.py`; its placeholder contracts and structural tests are not analytical acceptance.

## Data and workbook architecture

- [python/export_excel_inputs.py](../python/export_excel_inputs.py) verifies upstream artifacts and stages compact aggregates plus a versioned manifest. Eleven tables are byte-identical validated exports; `monthly_identification` is derived with Decimal aggregation and reconciled to monthly financials. The manifest records schemas, grains, scopes, hashes and row counts.
- [python/build_excel_workbook.py](../python/build_excel_workbook.py) prepares the template, summary tables, named controls, formula views, import plan and acceptance map. Nine of the twelve exported summaries feed native query tables. The input folder is read through the workbook's `SourceFolder` name.
- [reports/excel/finish_workbook.ps1](../reports/excel/finish_workbook.ps1) adds Power Queries and query-backed ListObjects, restores structured-reference formulas, creates three audit pivots and two slicers, refreshes, recalculates, checks formula errors and saves through Excel. It exports the four core views as PDFs.
- [reports/excel/validate_workbook.ps1](../reports/excel/validate_workbook.ps1) is the runtime acceptance script. It copies the workbook and CSVs to a new acceptance folder, changes `SourceFolder`, refreshes native queries and pivots, and compares Excel outputs with independent CSV calculations. The expanded checks passed in the separate owner-copy relocated run.

Financial controls use transaction country and calendar-month bounds. Customer views use assigned country, with frozen RFM at the exclusive 10 December 2011 cutoff. Financial dates do not change RFM scores. Formula dashboards use named controls and structured references; the two native slicers control their own audit pivots only. Cohort repeat denominators require complete individual 90-day observation through the actual last source timestamp. Final partial-month activity and future activity remain unavailable.

Native charts use visible axes and hidden-source-data plotting. Date controls validate first-of-month values and date order.

### Audit source correction

Hidden `Audit_Inputs` formulas derive disjoint United Kingdom, France and Other assigned-country groups; Other equals ALL minus United Kingdom minus France. `tblMigrationAudit` uses base `rfm_1` scoring and minimum 30 only, without scenario or minimum page filters. `tblRepeatAudit` uses complete-follow-up counts. Audit scope `(All)` includes all three disjoint groups. This fixes actual preaggregate double-counting: the retained [v3 scope regression](../outputs/excel_native_scope_regression.json) intentionally records failure at 11,279 versus 5,852 customers after clearing the slicer; v4 reconciles to 5,852.

## Official implementation references
